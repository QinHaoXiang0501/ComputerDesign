## Task 1 - Simple Frustration (Software Design & Architecture, MMU, 60%)

- Source spec: IMA knowledge base "课程" → "Task 1 Assessment Brief.pdf" (Manchester Metropolitan University, Yanyun Zhang).
- Delivered base version: `SimpleFrustration.java` (single main method, verified).
- **Key model insight (critical):** board is a CLOCKWISE LOOP of 18 positions; each player has a private Tail entered at the position just before their Home.
  - Red home=1 → divert at 18; Blue home=10 → divert at 9.
  - Tail has TAIL_LEN=3 slots INCLUDING End (T1, T2, End). distToEnd = stepsToD + TAIL_LEN.
  - Overshoot allowed (basic game): roll >= distToEnd → End. HIT ignored.
  - Position display: home→"HOME (Position X)", board→"Position X", tail→"TAIL (Tail Position k)", end→"END".
- Verified output reproduces all 3 brief basic scenarios EXACTLY (12,12,7,8 / 8,2,3,4,9 / 12,12,7,11), incl. "overshoots!" line.
- Dice: swappable — CLI args > FIXED_ROLLS const > random (brief explicitly recommends fixed sequence for testing).
- Refactor plan given to user: extract Player / Board / Dice(Strategy) / Game engine; later variations (exact-land, HIT, single-die, large-board, 4 players, undo) via Strategy/Factory patterns.

## Variation 1 — Precise Landing (exact landing)

- Renamed `ExactLandingWinningStrategy` -> `PreciseLandingStrategy` (implements WinningStrategy). `resolveEnd`: overshootSteps==0 -> END (win); else `board.bounceBack(player, overshootSteps)`.
- `Board.bounceBack(player, steps)` does the 折返+逆时针绕行: back down tail (End->T_{k-1}->...->T1), then anticlockwise from divert square; modulo handles any number of laps.
- Factory now wires `PreciseLandingStrategy` when `config.exactLanding()`. Added `GameConfig.enablePreciseLanding()` alias.
- Added `PreciseLandingDemo.java` (lightweight check): T2+roll5->Position17 (task example), T2+1->END, T2+3->T1, T2+4->Position18 — all verified.

## Variation 2 — HIT (victim sent back to Home)

- Renamed `SendHomeHitStrategy` -> `HitBackToHomeStrategy` (implements HitStrategy, `shouldSendVictimHome` returns true).
- **Bug fix (rule 5):** `Game.findVictim` now only matches `pos.isBoard()` (was `isBoard() || isHome()`), so a player sitting on their Home square is safe / cannot be hit.
- Tails are private per player (brief: "2 Tails, one for each player"), so collisions only occur on the shared main loop (`resolveHit` guards `landing.isBoard()`). No tail-hit possible.
- Factory wires `HitBackToHomeStrategy` when `config.hitEnabled()`. Added `GameConfig.enableHitBackToHome()` alias.
- Added `HitBackToHomeDemo.java`: (1) victim sent home (brief seq 8,2,3,4,9), (2) Red lands on Blue's home while Blue at home -> no hit (seq 9,12,8,7,2,8,3). Both verified.
- Note: fixed GBK compile error — replaced em-dash "—" with ASCII "-" in new file comments (Windows javac default charset is GBK).
